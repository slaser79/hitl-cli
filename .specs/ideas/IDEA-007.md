# Ideas Batch — hitl-cli (Batch 13)

## IDEA-181: "Smart" Request Retries with Human Feedback

- **Category**: UX / Feature
- **Problem**: If an agent sends a request while a human is in a meeting or driving, the agent often just times out and retries blindly, leading to notification fatigue.
- **Proposed Solution**: Allow the human to select "Remind me in 5/10/30 mins" from the mobile app's notification. The relay then communicates this delay back to the CLI/SDK, which automatically reschedules the notification for that specific time.
- **Business Value**: Respects human availability and significantly improves response rates while reducing user frustration.
- **Effort Estimate**: S

---

## IDEA-182: "Agent Group" Shared Identity (Cluster Support)

- **Category**: Security / Feature
- **Problem**: In a scaled environment (e.g., Kubernetes), each agent instance currently requires its own manual login, making it difficult to manage identities for a large cluster.
- **Proposed Solution**: A way to "share" a single agent identity across multiple instances using a shared secret or a short-lived "join code" generated by an already-authenticated instance.
- **Business Value**: Simplifies deployment and management for horizontally scaled agent fleets.
- **Effort Estimate**: M

---

## IDEA-183: `hitl-cli doctor --fix` (Automated Repair)

- **Category**: UX / Tech Debt
- **Problem**: Users often encounter simple configuration or authentication issues that the `doctor` command can diagnose, but they must then manually search for the fix.
- **Proposed Solution**: Enhance the `doctor` command to offer automated fixes for common problems, such as refreshing a stale OAuth token, fixing file permissions, or clearing corrupted config files.
- **Business Value**: Reduces support burden and improves the "Day 2" experience for all users.
- **Effort Estimate**: S

---

## IDEA-184: Integration with System-Level "Share" Sheet on Mobile

- **Category**: UX / Integration
- **Problem**: It is currently difficult for a human to send complex external data (e.g., a PDF report from an email) back to an agent without manually copying and pasting text.
- **Proposed Solution**: Enable the mobile app to receive files and data via the standard iOS/Android "Share" sheet. This data can then be associated with an active "request for file" from an agent.
- **Business Value**: Enables more complex human-to-agent data transfer workflows, such as reviewing and providing external documents.
- **Effort Estimate**: L

---

## IDEA-185: "Agent Pulse" — Live Context Streaming to Mobile

- **Category**: UX / Observability
- **Problem**: When reviewing a request, a human often lacks the immediate context of what the agent is *doing right now* (e.g., live logs or CPU usage).
- **Proposed Solution**: A command `hitl-cli stream-context` that pipes a window of live logs or system metrics directly to a dedicated "Context" tab in the mobile app's request view.
- **Business Value**: Provides instant context for decision-making without the human needing to be at their desktop.
- **Effort Estimate**: M

---

## IDEA-186: "Auto-Delegate" Rules for Team Escalation

- **Category**: Feature
- **Problem**: Critical agent requests can be blocked indefinitely if the primary human user is unavailable or forgets their phone.
- **Proposed Solution**: Allow users to define "Global Delegation Rules" on the relay (e.g., "If no response in 5 minutes, escalate to User B"). The relay handles the rerouting automatically.
- **Business Value**: Improves overall system reliability and ensures high-priority tasks are always addressed by *someone* in the team.
- **Effort Estimate**: M

---

## IDEA-187: SDK support for "Callback-Based" Human Interaction

- **Category**: SDK / Architecture
- **Problem**: The current SDK uses a synchronous `await hitl.request_input()` pattern, which can cause issues if the agent process needs to restart during a long-running interaction.
- **Proposed Solution**: Provide a callback or webhook-based SDK pattern where the agent registers a "resume point" (e.g., a function or URL) that is triggered by the SDK once the human responds.
- **Business Value**: Enables more robust, long-running agentic workflows that can survive process restarts.
- **Effort Estimate**: M

---

## IDEA-188: "Cost-Aware" HITL Interventions

- **Category**: Business Value / UX
- **Problem**: Organizations have no way to track the actual "cost" of human-in-the-loop interventions (e.g., the time value of a senior engineer's attention).
- **Proposed Solution**: Add a `--cost-tier` or `--impact` flag to the `request` command. The mobile app and relay can then track and aggregate the total "cost of intervention" across the agent fleet.
- **Business Value**: Helps organizations optimize their human-AI collaboration by identifying high-cost bottlenecks.
- **Effort Estimate**: S

---

## IDEA-189: Support for Hardware Security Keys (FIDO2) on Mobile

- **Category**: Security
- **Problem**: For extremely high-risk operations (e.g., production database wipes), a simple phone tap might not be considered secure enough.
- **Proposed Solution**: Allow the mobile app to require a physical security key (e.g., YubiKey via NFC) to sign and authorize specific high-priority requests.
- **Business Value**: Provides bank-grade security for the most critical autonomous system actions.
- **Effort Estimate**: L

---

## IDEA-190: "Hands-Free" Voice Approval for Mobile

- **Category**: UX
- **Problem**: Developers and operators might be busy with their hands or driving when a critical HITL notification arrives.
- **Proposed Solution**: Integrate the mobile app with Siri and Google Assistant, allowing users to "Approve" or "Reject" requests via voice commands without unlocking their phone.
- **Business Value**: Increases the accessibility and responsiveness of the system in all environments.
- **Effort Estimate**: M

---

## IDEA-191: "Time-Travel" System Snapshot on Approval

- **Category**: Reliability / Compliance
- **Problem**: In post-mortem analysis, it is difficult to know exactly what the *agent's* environment looked like at the precise moment a human made a choice.
- **Proposed Solution**: When a human responds, the CLI optionally captures a "snapshot" of the local system state (env vars, git status, active processes) and stores it as metadata with the response.
- **Business Value**: Invaluable for auditing and debugging failures in complex human-in-the-loop systems.
- **Effort Estimate**: M

---

## IDEA-192: SDK support for "Human-Driven Remote Config"

- **Category**: SDK / Feature
- **Problem**: Dynamically adjusting an agent's behavior often requires code changes or manually setting environment variables on the host machine.
- **Proposed Solution**: A pattern where an agent calls `config = await hitl.get_config(schema)`, which prompts the human to fill out a structured form on their mobile device to configure the agent's next steps.
- **Business Value**: Turns the mobile app into a remote configuration console for autonomous agents.
- **Effort Estimate**: M

---

## IDEA-193: Global "Quiet Hours" Group Policy

- **Category**: Integration / UX
- **Problem**: Managing "Quiet Hours" individually for every agent instance is tedious for large teams.
- **Proposed Solution**: Support defining a "Global Quiet Hours" policy at the relay level (manageable via CLI) that applies to all agents within a specific team or organization.
- **Business Value**: Protects team well-being and reduces administrative overhead for large-scale deployments.
- **Effort Estimate**: S

---

## IDEA-194: "Shadow Concordance" Mode (Trust Building)

- **Category**: Feature / Quality
- **Problem**: Teams are often hesitant to move from human-heavy to agent-heavy workflows because they lack data on the agent's decision-making quality.
- **Proposed Solution**: A mode where the agent makes a choice AND asks the human. The CLI records both and generates a "concordance report" showing how often the agent and human agreed.
- **Business Value**: Safely builds data-driven confidence in autonomous systems over time.
- **Effort Estimate**: M

---

## IDEA-195: Integration with Jupyter Notebooks (IPython Magics)

- **Category**: UX / DX
- **Problem**: Data scientists working in Jupyter notebooks currently have no easy way to pause execution and ask a human to review a plot or a sample of data.
- **Proposed Solution**: A specialized Jupyter extension or `%hitl` magic command that allows a cell's output (image or table) to be sent to a human for review directly from the notebook.
- **Business Value**: Brings the power of HITL to the data science and ML research community.
- **Effort Estimate**: S
